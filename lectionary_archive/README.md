# Lectionary Archive Search

Builds a searchable database from the Discipleship Ministries lectionary
content library (https://www.umcdiscipleship.org/content-library/lectionary),
so you can search past worship-planning content by topic, scripture
reference, series, date, or content type, instead of paging through the
site's non-searchable archive. Published as a static, browser-searchable
site via GitHub Pages, kept up to date automatically by GitHub Actions --
no local machine needs to be running anything.

## How it works, end to end

1. `scraper.py` crawls the year-by-year archive (2016-present) and every
   linked sub-page per week (Preaching Notes, Hymn Suggestions, Children's
   Message, etc.), storing everything in a SQLite database with a full-text
   index (`lectionary_archive/data/lectionary.db`, tracked in this repo).
2. `export_static.py` flattens that database into `docs/data.json`.
3. `docs/index.html` is a self-contained search page: it fetches
   `data.json` once and does searching, filtering, snippet highlighting,
   and pagination entirely in JavaScript in the visitor's browser -- no
   server needed, which is why this works on GitHub Pages.
4. `.github/workflows/update-lectionary-archive.yml` runs steps 1-2 on a
   weekly schedule (Sundays) and pushes the result, so the published site
   stays current without you doing anything.

**Heads up:** this publishes the archive's actual scraped text, not just
links to it, at a public URL anyone can visit -- even though the GitHub
repo itself is private, GitHub Pages doesn't inherit that privacy on the
free plan. This setup assumes you're fine with that.

## One-time setup

1. **Push this to your default branch** if it isn't already (Actions
   `schedule` triggers only run off the default branch).
2. **Turn on GitHub Pages:** repo -> **Settings** -> **Pages** -> under
   "Build and deployment," set **Source** to "Deploy from a branch," pick
   your branch, and set the folder to **/docs**. Save. You'll get a URL
   like `https://<your-username>.github.io/worship-planning/` -- it can
   take a minute or two to go live the first time.
3. **Nothing else to configure for Actions** -- `permissions: contents:
   write` in the workflow plus GitHub's automatically-provided credentials
   are enough for it to push its own commits back to the repo. No secrets
   or tokens to set up by hand.
4. **Kick off the first run:** go to the repo's **Actions** tab -> "Update
   lectionary archive" -> **Run workflow**. This does the full initial
   crawl (2016-present, on the order of a thousand pages), so it'll take
   a while -- check progress under Actions while it runs. Every run after
   this one only fetches weeks it hasn't seen before, so they're much
   quicker.

That's the whole setup. Going forward, it runs itself every Sunday; you can
also trigger it manually from the Actions tab any time.

## How it's structured

- `weeks` -- one row per lectionary Sunday/occasion: date, liturgical name
  (e.g. "Second Sunday in Lent, Year A"), series name, theme title, teaser,
  liturgical colors.
- `scripture_refs` -- the Hebrew Bible/Psalm/Epistle/Gospel readings for each
  week, linked back to the Vanderbilt Revised Common Lectionary site.
- `pages` -- the actual content: one row per sub-page per week (planning
  notes, preaching notes, hymn suggestions, etc.), with both HTML and
  plain-text body content.
- `search_index` -- a SQLite FTS5 full-text index over all of the above.
- `docs/data.json` -- a flat export of `search_index`, regenerated by
  `export_static.py`, used only by the static GitHub Pages site.

## Running it locally instead (optional)

Everything above runs on GitHub's infrastructure. You don't need any of
this -- it's here in case you ever want to search, crawl, or develop from
your own machine instead of (or in addition to) the published site.

### Setup

```
cd lectionary_archive
pip install -r requirements.txt
```

The scraper makes real HTTP requests to umcdiscipleship.org, so it needs a
machine with normal internet access -- it won't work in a network-sandboxed
environment. It's polite by default: descriptive User-Agent, checks
`robots.txt`, rate-limits requests (1/second by default), and caches fetched
pages to disk.

### Build/update the database

```
python scraper.py
```

Useful flags: `--start-year 2023` (narrower range), `--delay 2.0` (slower),
`--refresh` (ignore cache, re-fetch everything).

### Search

```
python search.py "forgiveness"
python search.py "grief" --type childrens_message
python search.py --scripture "John 3"
python search.py --series "Renewed in Mercy"
python search.py "baptism" --after 2023-01-01 --before 2024-12-31
```

Or a small local web UI: `python webapp.py`, then open
http://localhost:8000.

### A real double-clickable macOS app

`mac_app/` has AppleScript sources for two tiny macOS apps: one starts the
search server and opens it in your browser, the other stops it -- no
Terminal window, can be dragged straight onto the Dock. Compile them on
your own Mac (edit `appDir` in both `.applescript` files first if your
clone isn't at `~/Documents/GitHub/worship-planning/lectionary_archive`):

```
cd ~/Documents/GitHub/worship-planning/lectionary_archive/mac_app
osacompile -o "Lectionary Search.app" "Lectionary Search.applescript"
osacompile -o "Stop Lectionary Search.app" "Stop Lectionary Search.applescript"
```

`Launch Lectionary Search.command` is a simpler double-click launcher that
opens a visible Terminal window instead (useful for seeing errors).

### Keeping a local copy up to date automatically (macOS launchd)

If you want your Mac to independently crawl and publish on its own schedule
(redundant with GitHub Actions, but harmless -- both just commit/push when
something changed), `com.umcdiscipleship.lectionary-scraper.plist` is a
`launchd` job that runs `update_and_publish.sh` every Sunday at 6:00 AM.

1. Confirm your Python path (`which python3`) and update it in
   `update_and_publish.sh` if it's not `/usr/bin/python3` (launchd uses a
   minimal PATH that may not match your Terminal's).
2. Confirm `git push` doesn't prompt for a password when run by hand.
3. Confirm the paths in the `.plist` and in `update_and_publish.sh` match
   where you cloned this repo.
4. Install it:
   ```
   cp com.umcdiscipleship.lectionary-scraper.plist ~/Library/LaunchAgents/
   launchctl load ~/Library/LaunchAgents/com.umcdiscipleship.lectionary-scraper.plist
   ```

Useful commands: `launchctl start com.umcdiscipleship.lectionary-scraper`
(run now), `launchctl unload ~/Library/LaunchAgents/com.umcdiscipleship.lectionary-scraper.plist`
(turn off -- do this if you'd rather rely on GitHub Actions alone).
